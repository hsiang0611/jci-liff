# 龍井青商會員專區（LINE LIFF 版）

在 LINE 裡開啟的會員 App：會員用姓名＋手機綁定 LINE 後，依「會員」名冊上的角色取得不同權限；
幹部可以發布活動與消息，會長、秘書長與管理員可以用 LINE 推播通知。所有資料都存在一份 Google 試算表，秘書處直接在試算表維護名冊。

```
 會員手機 (LINE App)
   │  圖文選單 / 推播訊息按鈕
   ▼
 LIFF 前端（liff/，放 GitHub Pages）──── LINE Login：取得 ID Token
   │  POST { action, idToken, data }
   ▼
 Apps Script 網頁應用程式（gas/）
   ├─ 向 LINE 驗證 ID Token → 取得 userId
   ├─ 依「會員」「權限」工作表決定可做什麼
   ├─ 讀寫試算表（活動、報名、消息…）
   └─ 呼叫 Messaging API 推播 ──► 會員收到 LINE 訊息
```

## 檔案

| 位置 | 用途 |
|---|---|
| `apps-script-單一檔案.gs` | 後端全部程式合併成一個檔案，**部署時貼這個就好** |
| `gas/` | 同樣的後端程式，分檔版本（給想用 clasp 管理版本的人） |
| `liff/` | 前端，資料夾裡的 `index.html`、`css`、`js`、`img` 上傳到 GitHub Pages 或任何 HTTPS 主機 |
| `liff/js/config.js` | 部署時唯一要改的前端檔案（**更新時不要用新檔蓋掉自己填好的版本**） |
| `liff/poster.html` | 招募海報（A4，可列印或存成 PDF），App 的「我的 → 招募海報」會開它 |
| `liff/img/richmenu/` | 依身分切換的四張圖文選單圖（訪客、預備會員、會員、幹部），建立選單時後端會從網站讀取 |
| `cloudflare/worker.js` | 加速層（Cloudflare Worker，選用）：放在 App 和 Apps Script 中間的暫存，讓讀取變快、閒置後不用等；見「加速層」一節 |

直接用瀏覽器打開 `liff/index.html` 就會進入**示範模式**（假資料、不連 LINE），上方可以切換「會長／秘書長／財務長／理事／會員／特友／預備會員／訪客」看權限差異。

## 角色與權限

權限寫在試算表的「權限」工作表，勾選框打勾即生效，不用改程式。預設如下：

| 角色 | 等級 | 通訊錄 | 管理活動 | 管理消息 | 報名名單 | 發送推播 | 管理會員 | 管理會費 | 代為報名 |
|---|---|---|---|---|---|---|---|---|---|
| 會長 | 90 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | |
| 秘書長 | 90 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 管理員（秘書處、系統管理者，不算幹部） | 90 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 財務長 | 80 | ✓ | ✓ | ✓ | ✓ | | | ✓ | |
| 副會長 | 80 | ✓ | ✓ | ✓ | ✓ | | | | |
| 理事 | 75 | ✓ | ✓ | ✓ | ✓ | | | | |
| 監事 | 75 | ✓ | ✓ | ✓ | ✓ | | | | |
| 法制顧問 | 70 | ✓ | ✓ | ✓ | ✓ | | | | |
| 幹部（主委等其他幹部） | 70 | ✓ | ✓ | ✓ | ✓ | | | | |
| 會員 | 50 | ✓ | | | | | | | |
| 特友 | 40 | ✓ | | | | | | | |
| 預備會員 | 20 | | | | | | | | |
| 訪客（未綁定） | 0 | | | | | | | | |

- 通訊錄依角色分組，順序就是「權限」表由上到下的順序（等級高的在前）。想讓副會長排在財務長前面，把兩列對調即可。
- **職稱**還是可以另外填（例如角色「理事」、職稱「常務理事」）；職稱跟角色一樣時，畫面上只顯示一次。
- 「本屆幹部」包含角色是會長～法制顧問、幹部的人，以及有填自訂職稱（例如「公關主委」「特友會長」）的人；管理員不算幹部。
- 活動與消息的「可見對象」選的是**等級**，同等級的角色一起列出，例如「理事、監事以上」＝理監事＋財務長、副會長、會長、秘書長、管理員；「法制顧問、幹部以上」＝所有幹部；選「公開」連未綁定的人都看得到，也能報名（需填姓名手機，適合招募新朋友）。
- 法制顧問預設和「幹部」同等級（看不到「理事、監事以上」的資料）；要讓他參加理監事會，把等級改成 75 即可。
- 可以自行新增角色（例如「顧問」等級 60），在「權限」表加一列即可；等級 70 以上的自訂角色會算幹部。
- 「發送推播」預設只給會長、秘書長、管理員，因為每則推播都會用掉訊息額度（見下方）。發送通知時「指定角色 → 勾選所有幹部」可以一次選好全部幹部。
- 「代為報名」預設只給秘書長與管理員（秘書處）；會長或其他幹部也要的話，在「權限」表勾選即可（需要同時有「查看報名名單」才看得到入口）。
- 停用的會員一律視為訪客。

## 還沒有 LINE 官方帳號？

推播一定要有官方帳號，但其他功能不用。有兩種走法：

### 方式一：先建官方帳號（建議，免費，約 15 分鐘）

1. 到 [LINE for Business 台灣官網](https://tw.linebiz.com/) 的 LINE 官方帳號頁面點「免費開設帳號」，用 LINE 帳號登入（LINE Business ID）。
2. 帳號名稱填「龍井國際青年商會」，業種選最接近的團體／組織類別，填聯絡 email 與組織資料。
   建好就是「一般帳號」，立即可用，預設是免費的輕用量方案。
3. 「認證帳號」是選用的：可以被搜尋到、比較有公信力，但要另外送審並附文件；不影響本系統任何功能，之後再申請也可以。
4. **帳號不要只綁在一個人身上**：在 LINE Official Account Manager「設定 → 權限管理」至少加入兩位管理員（例如會長與秘書長），每年交接時更新。
   Google 試算表與 Apps Script 也建議用會務專用的 Google 帳號建立，交接時才不會卡在個人帳號。
5. 接著照下方「部署步驟」做。注意：自 2024 年 9 月起，Messaging API channel 不能再從 LINE Developers 直接建立，必須在官方帳號後台「設定 → Messaging API」啟用；
   啟用時選的 Provider **之後不能更改**，要和 LINE Login channel 選同一個。

### 方式二：先上線，之後再接官方帳號

沒有官方帳號時，系統會自動隱藏推播相關按鈕，其他照常運作：

| 可以用 | 要等官方帳號 |
|---|---|
| 會員綁定、角色權限 | 發送通知（推播） |
| 活動、報名、報名名單 | 每日活動提醒、壽星祝福 |
| 消息公告 | 圖文選單 |
| 會員通訊錄、會員管理、綁定審核 | 加好友提示、聊天室傳「活動」自動回覆 |

做法：

1. LINE Developers 建立 Provider 和 **LINE Login channel**，新增 LIFF（同下方步驟 2 的 LINE Login 部分）。
   「Linked LINE Official Account」留空，Add friend option 選 **Off**。
2. 試算表「設定 LINE 金鑰」時，Channel access token **留空**（按確定跳過），其他照填，然後部署。
3. `config.js` 的 `OA_BASIC_ID` 留空。
4. 沒有圖文選單，入口改用連結：把 `https://liff.line.me/你的LIFF_ID` 貼到會內 LINE 群組的「記事本」或「公告」並置頂，
   也可以加上 `?to=events` 直接開活動列表。

之後建立官方帳號時：

1. 官方帳號後台啟用 Messaging API，**選同一個 Provider**。這樣已經綁定的會員不用重新綁定（同一個 Provider 底下，同一個人的 LINE userId 相同）。
2. 發行 Channel access token，到試算表「設定 LINE 金鑰」填入（金鑰立即生效，不用重新部署）。
3. `config.js` 填 `OA_BASIC_ID`；LINE Login channel 連結官方帳號，LIFF 的 Add friend option 改成 On (aggressive)。
4. 設定圖文選單、Webhook、每日提醒（下方步驟 5、6），並在群組公告請大家加官方帳號好友，才收得到通知。

## 部署步驟

### 1. 建立試算表與後端

1. 建立一份新的 Google 試算表，命名例如「龍井青商會員系統」。
2. 選單「擴充功能 → Apps Script」，把預設的 `程式碼.gs` 內容全部刪掉，貼上 `apps-script-單一檔案.gs` 的內容，存檔。
3. 左側「專案設定（齒輪）」→ 時區選「(GMT+08:00) 台北」。
4. 回到試算表重新整理，上方會出現「會員系統」選單 → 執行「1. 初始化／修復工作表」。
   第一次執行 Google 會要求授權，出現「這個應用程式未經 Google 驗證」時按「進階 → 前往（不安全）」，這是你自己的程式。
5. 在「會員」工作表填入會員名冊。**至少把自己的角色設成「管理員」（或會長、秘書長）**。手機欄已設成文字格式，開頭的 0 不會不見。
   想先測試可以用選單「載入示範資料」。

### 2. LINE Developers 設定

到 [LINE Developers Console](https://developers.line.biz/console/)：

1. 建立（或使用現有的）**Provider**，例如「龍井國際青年商會」。
2. **Messaging API channel**：如果已經有 LINE 官方帳號，在 [LINE Official Account Manager](https://manager.line.biz/) →「設定 → Messaging API」啟用，選擇**同一個 Provider**。
   - 到 Developers Console 該 channel 的「Messaging API」分頁，最下方發行 **Channel access token (long-lived)**，複製起來。
   - 記下官方帳號的 **Basic ID**（@ 開頭）。
3. **LINE Login channel**：同一個 Provider 底下新增，App types 勾「Web app」。
   - 「Basic settings」記下 **Channel ID**；「Linked LINE Official Account」選你的官方帳號（App 才能判斷會員有沒有加好友）。
   - 「LIFF」分頁 → Add：Size 選 **Full**；Endpoint URL 先隨便填 `https://example.com`（第 4 步再改）；Scopes 勾 **openid** 和 **profile**；Add friend option 選 **On (aggressive)**（第一次開啟時邀請加官方帳號好友）；Scan QR、Module mode 不用勾。
   - 建好後記下 **LIFF ID**（例如 `2001234567-AbCdEfGh`）。
   - ⚠️ 新建的 LINE Login channel 狀態是 **Developing**，只有 channel 管理員和測試人員打得開。正式給會員用前，點頻道名稱旁的「Developing」改成 **Published**。
   - 想讓會員能把活動分享到聊天室：LIFF 設定裡把 **shareTargetPicker** 打開。

> ⚠️ LINE Login channel 和 Messaging API channel **一定要在同一個 Provider**。不同 Provider 下同一個人的 userId 不一樣，推播會找不到人。

### 3. 設定金鑰並部署後端

1. 試算表選單「會員系統 → 2. 設定 LINE 金鑰」，依序貼上：Channel access token、LINE Login Channel ID、LIFF ID、組織名稱。
2. 「會員系統 → 3. 檢查設定」，確認都是 ✅。
3. Apps Script 編輯器右上「部署 → 新增部署作業」→ 類型「網頁應用程式」：
   - 執行身分：**我**
   - 誰可以存取：**所有人**
4. 複製部署後的網址（`https://script.google.com/macros/s/……/exec`）。

### 4. 部署前端（GitHub Pages）

1. 編輯 `liff/js/config.js`：

   ```js
   LIFF_ID: '2001234567-AbCdEfGh',
   API_URL: 'https://script.google.com/macros/s/……/exec',
   OA_BASIC_ID: '@123abcde',
   ```

   這幾個值都不是密碼，放在公開的 GitHub 沒問題；真正的金鑰（Channel access token）只存在 Apps Script 裡。
2. 在 GitHub 建立 repository（例如 `jci-liff`），把 `liff/` 資料夾**裡面的** `index.html` 和 `css`、`js`、`img` 三個資料夾一起拖進上傳框（用 Chrome 或 Edge 拖曳才能帶資料夾），上傳到根目錄。
   上傳後在 repository 首頁要看得到 `index.html` 和這三個資料夾。少了 `css` 或 `js` 會開不起來（頁面會顯示缺哪個檔案）；少了 `img` 只是看不到會徽。
3. repository 的「Settings → Pages」，Source 選 `main` 分支、`/ (root)`，存檔後會得到網址 `https://帳號.github.io/jci-liff/`。
4. 回 LINE Developers 的 LIFF 設定，把 Endpoint URL 改成這個網址。
5. 用手機 LINE 打開 `https://liff.line.me/你的LIFF_ID`，就會進入會員專區。

### 5. 圖文選單（會員的入口）

在 LINE Official Account Manager →「圖文選單」建立，按鈕動作選「連結」。
`圖文選單` 資料夾有兩張做好的圖（2500×1686，JPG，小於 1 MB）：

- `圖文選單-A-四格`：版型選大型「四格（2×2）」，A 左上＝會員專區、B 右上＝近期活動、C 左下＝最新消息、D 右下＝通訊錄。
- `圖文選單-B-上一下三`：版型選大型「上方一格、下方三格」，A 上方＝會員專區、B／C／D 下方由左到右＝近期活動、最新消息、通訊錄。

其他可用的連結：`?to=docs`（文件庫）、`?to=me`（我的）、`?to=admin/attendance`（出席統計，只有幹部打得開）。

#### 進階：依身分切換圖文選單（建議）

訪客、預備會員、會員、幹部看到不同的選單。圖片在 `liff/img/richmenu/`（四張），網站上傳後：

1. 試算表選單「會員系統 → 建立依身分切換的圖文選單」，輸入網站網址（`index.html` 所在的資料夾，例如 `https://帳號.github.io/jci/`）。
2. 系統會建立四組選單：
   - **訪客**（未綁定、停用，預設）：認識我們／近期活動／最新消息／會員登入
   - **預備會員**（已綁定但不能看通訊錄的角色）：會員專區／近期活動／最新消息／入會進度
   - **會員**（能看通訊錄的角色，例如會員、特友）：會員專區／近期活動／最新消息／通訊錄
   - **幹部**（有任何管理權限的角色）：會員專區／近期活動／最新消息／通訊錄／出席統計／管理功能
   - 預備會員通過入會、角色改成「會員」後，下次打開會員專區就會換成會員選單。
3. 之後有人綁定、角色改變或被停用，他**下次打開會員專區時**選單會自動換掉。直接在試算表改了很多人的角色，可以按「重新套用圖文選單」一次換好。
4. 不想用了：「移除依身分切換的圖文選單」，會恢復官方帳號後台設定的選單。

啟用後，官方帳號後台（OA Manager）設定的圖文選單不會再顯示。切換選單不花訊息額度。

### 6. Webhook（選用）與排程

- **Webhook**：Developers Console → Messaging API → Webhook URL 填 Apps Script 網址並開啟「Use webhook」。
  開啟後：加好友時自動回歡迎訊息；有人傳「活動」會回覆近期活動卡片（依對方角色）；傳「會員」回覆會員專區按鈕。**回覆訊息不計費**。
  按「Verify」若顯示非 200，是因為 Apps Script 會先轉址，實際傳訊息測試有回應即可。
  若官方帳號同時要用 OA Manager 的自動回應，「回應設定」裡聊天與 Webhook 可以同時開。
- **每日活動提醒**：選單「安裝每日活動提醒（18:00）」，每天傍晚提醒「明天」活動的報名者，每場只提醒一次，改期會重新提醒。
- **壽星祝福**（選用）：選單「安裝壽星祝福（09:00）」，需要在「會員」填生日。
- **每週自動備份**（建議）：選單「安裝每週自動備份（週日 03:00）」。每週把整份試算表複製一份到雲端硬碟「龍井國際青年商會會員系統備份」資料夾，保留最近 12 份，較舊的移到垃圾桶（30 天內可救回）。裝好後先按一次「立即備份試算表」確認。
- **預約推播**：不用另外安裝。有人預約時系統會自動裝一個每 5 分鐘的檢查排程，全部送完會自己移除。

### 7. 加速層（選用，建議：Cloudflare Worker）

Apps Script 每次呼叫通常要 1～3 秒，閒置一陣子後的第一次可能更久。加速層是一個放在 App 和 Apps Script 中間的小程式（Cloudflare Worker，免費方案就夠）：

- 讀取類的動作（首頁、活動、通訊錄、名單、統計…）的回應會暫存在 Cloudflare 的 D1 資料庫。同一個人再打開、或其他會員看同一份通訊錄，直接從暫存回（約 0.1～0.3 秒）。
- 任何寫入（報名、點名、改資料…）經過加速層時，暫存全部作廢；秘書處直接改試算表、排程寫入時，Apps Script 也會通知加速層作廢。會員看到的資料和以前一樣是最新的。
- 每 5 分鐘叫醒 Apps Script 一次並預熱它的暫存，減少「閒置後第一個人等很久」。
- 給誰看暫存之前，一定先用 LINE 的公鑰驗證登入憑證，確認是本人；共用的暫存（通訊錄等）只給同一個角色的人，角色以 Apps Script 回傳的為準。
- 試算表還是唯一的資料來源，加速層壞了 App 會自動改走 Apps Script（要在 `config.js` 填 `GAS_URL`）。

**建立步驟（約 15 分鐘，全部在 Cloudflare 網頁後台點選，不用安裝任何東西）**

1. 到 [dash.cloudflare.com](https://dash.cloudflare.com/) 註冊免費帳號（不需要信用卡、不需要自己的網域）。
2. 左側「Storage & Databases → D1 SQL Database」→「Create Database」，名稱 `jci-cache`，其他預設。
3. 左側「Workers & Pages」→「Create」→「Start with Hello World!」→ 名稱 `jci-api` →「Deploy」。
4. 進入這個 Worker →「Edit code」→ 把 `cloudflare/worker.js` 的內容整份貼上取代 →「Deploy」。
5. Worker 的「Settings → Bindings」→「Add」→「D1 database」：Variable name 填 `DB`，選 `jci-cache` → Deploy。
6. 「Settings → Variables and Secrets」→「Add」三個：
   - `GAS_URL`（Text）：Apps Script 網頁應用程式網址（…/exec）
   - `LINE_LOGIN_CHANNEL_ID`（Text）：和試算表「設定 LINE 金鑰」填的一樣
   - `EDGE_SECRET`（**Secret**）：自己想一串長密碼，例如 20 個以上的英數字
7. 「Settings → Triggers → Cron Triggers」→「Add」→ 填 `*/5 * * * *`（每 5 分鐘）。
8. 「Settings → Domains & Routes」找到 Worker 的網址，長得像 `https://jci-api.你的帳號.workers.dev`，複製起來。
9. 回到試算表選單「會員系統 → 設定加速層（Cloudflare）」，貼上 Worker 網址和同一串 `EDGE_SECRET`。它會立刻測試，顯示「加速層連線正常」才算完成。
10. 網站的 `js/config.js`：`API_URL` 改成 Worker 網址，原本的 Apps Script 網址改填到 `GAS_URL`（加速層連不上時自動改走這裡）。上傳 `config.js`。
11. 用手機打開會員專區，「我的 → 連線狀況」應該顯示「加速層使用中」；多開幾個畫面會看到「命中暫存」。

用量：免費方案每天 10 萬次請求、D1 每天 10 萬次寫入，以本會規模綽綽有餘。
不想用了：試算表選單「設定加速層」輸入「停用」，並把 `config.js` 的 `API_URL` 改回 Apps Script 網址。

會寫程式的人也可以用 `cloudflare/wrangler.toml` 搭配 `wrangler deploy` 部署。

## 訊息額度要注意

台灣官方帳號的「輕用量」方案（免費）每月 **200 則**。push、multicast、broadcast 都是依**收到的人數**計算：
發一則通知給 60 位會員就用掉 60 則。回覆（reply）不計費。（2026 年 11 月起中用量、高用量月費調漲，免費則數不變。）

系統已做的保護：

- 發送通知頁會即時顯示本月已用額度與這次會用掉幾則，額度不夠時直接擋下，不會發到一半。
- 新增活動、發布消息時「同時推播」預設**不勾選**。
- 發送權限預設只有會長、秘書長、管理員。
- 會員平常看活動、看消息都是自己打開 LIFF，或在聊天室傳「活動」取得回覆，這些都不花額度。

## 例會當天怎麼報到

1. 幹部打開活動頁，按「報到 QR code」，把畫面投影出來或列印放在報到桌（也可以按「複製連結」貼到群組，但這樣在家也能報到，請自行斟酌）。
2. 會員用 LINE 的掃描功能（LINE 首頁右上角）掃 QR code → 按「我到了，報到」。沒事先報名的會員掃碼也能報到，系統會自動補登報名。
3. 沒帶手機的人，幹部在活動頁的報名名單勾「出席」；沒報名又沒手機的，按「現場加入」。
4. 報到時間是活動開始前 2 小時到結束後 3 小時；過了之後幹部仍可以點名補登。
5. 如果 QR code 外流，按「換一組報到碼」，舊的立刻失效。

出席統計只看「出席」欄有沒有時間，所以事後在試算表「報名」工作表補填也可以。

   - **這次會跳出授權視窗**（新增了雲端硬碟權限，自動備份要用），請用管理這份試算表的帳號按「允許」。**沒有先授權，下一步部署後會員專區會打不開。**

   - 「類別」與「入會條件」會先填好預設值，請依本會實際情況修改（入會條件預設：例會 3 次、公益服務 1 次、訓練 1 次）。
3. 「部署 → 管理部署作業 → 鉛筆 → 版本選『新版本』→ 部署」。

## 日常維護

- **之後要改程式時（版本號）**：前端改了，就把 `js/app.js` 最上方的 `APP_VERSION` 和 `index.html` 裡所有的 `?v=` 改成同一個新值（例如 `2026.11.15`）。後端也改了，再把 `Schema.gs` 的 `APP_VERSION` 和 `app.js` 的 `MIN_BACKEND_VERSION` 改成同一個值。會員手機上的舊檔會被提示更新，不會卡在舊版。
- **上傳網站檔案的順序**：在 GitHub 把 `index.html`、`css`、`js` **一次拖進上傳框**（同一次上傳）。要分開傳的話，`index.html` 最後傳。先傳 `index.html` 的話，那一兩分鐘內打開的手機會把舊的 `js` 暫存 10 分鐘，畫面會一直出現「系統已更新」（這版起 App 會自己偵測並重新下載）。
- **試算表直接修改後**：App 會立刻看到（有修改觸發器）。如果觸發器被刪掉，最慢 10 分鐘也會更新；重新執行「1. 初始化／修復工作表」會裝回來。

- **新增會員、改姓名或手機**：直接改「會員」工作表。
- **調整角色、停用、解除 LINE 綁定**：試算表或 App 的「我的 → 會員管理」都可以。
- **會員換手機／換 LINE 帳號**：在會員管理按「解除 LINE 綁定」，請對方重新綁定。
- **名冊比對不到的人**：會出現在「我的 → 綁定審核」，可以綁到既有會員或新增為會員。
  想在有人申請時收到 LINE 通知，到 Apps Script「專案設定 → 指令碼屬性」新增 `NOTIFY_ADMIN_ON_REQUEST` = `true`。
- **修改後端程式後**：一定要「部署 → 管理部署作業 → 編輯（鉛筆）→ 版本選『新版本』→ 部署」，網址才會維持不變。直接「新增部署作業」會產生新網址。
- 推播紀錄都在「推播紀錄」工作表。
- **文件庫**：App「文件庫 → 新增文件」或直接在「文件」工作表貼雲端硬碟連結；連結要先在雲端硬碟設成「知道連結的使用者可檢視」。
- **出席統計算哪些活動**：「類別」工作表勾了「計入例會出席」的類別（預設只有例會）且已經開始的活動算「例會」，其他類別算「其他活動」；草稿與取消的不算。
- **新增或修改類別**：在「類別」工作表加一列：類型（活動／消息／文件）、名稱、顏色（例如 `#8E5BB5`，可留空由系統配色）。表上的順序就是 App 下拉選單與文件庫分組的順序。改名或刪除類別不會改到已存在的活動，編輯舊活動時會保留原本的類別。
- **入會條件**：「入會條件」工作表一列一個條件：適用角色（例如預備會員）、條件名稱、活動類別（可用「、」寫多個，寫「全部」代表任何活動都算）、次數。出席一樣以掃碼報到或幹部點名為準，歷年累計。
- **歷屆會長、歷屆主席**：在試算表的「歷屆會長」「歷屆主席」工作表維護，一列一位：
  - 「年度」填 `2010` 或 `民國99年` 都可以（排序會換算成西元）；「屆別」「備註」選填。
  - 「姓名」是**下拉選單**，從「會員」名單選；選好後「會員編號」「公司/職業」會自動帶入（灰色欄，不用自己填），姓名也會統一成名冊上的寫法。
    不在名單的人（例如已退會的老會長）可以直接打字，會出現紅色小三角形提醒，但可以儲存，公司可以自己填。
  - 「歷屆主席」多一欄「職稱」，留空就是「主席」；要區分的話填「特友會主席」「監事會主席」等。
  - 一次貼上很多列、或會員改了名字、公司之後，用選單「重新帶入歷屆會長、主席的會員資料」整批更新。
  - App 裡「歷屆會長 →（歷屆主席）→ 新增」也可以，一樣從會員名單選人；旁邊的鉛筆可以修改或刪除。年度交接時卸任的會長、主席會自動加進去。
  - 同一年同一個人只會出現一次；現任會長（角色或職稱是會長）、現任主席會自動列在最後並標「現任」。
- **年度交接**：「我的 → 年度交接」。步驟 1 勾選要存檔的卸任幹部（預設勾選本屆所有幹部），步驟 2 直接改每個人的新角色與職稱，「勾選的卸任幹部：角色改回會員、清空職稱」可以一次清掉，再幫新年度幹部選角色（會長、理事…）。完成後試算表「歷屆幹部」工作表會多一個年度，卸任的會長、主席也會加進「歷屆會長」「歷屆主席」。同一年度重做會覆蓋，不會重複。自己的角色不能在這裡改（避免把自己降級鎖在外面）。
- **調查**：首頁「調查」或「我的 → 調查」。建立後可以「提前結束」「重新開放」「複製結果」；回覆在「調查回覆」工作表。修改選項文字後，選舊文字的回覆就不會再計算。
- **會友商家**：會員在「我的 → 我的商家」自行登錄；秘書處也可以直接在「會員」工作表的「商家名稱」等欄填寫。商家的電話跟通訊錄一樣，只有本人同意顯示才會出現。
- **預約推播**：在「排程推播」工作表可以看到所有預約與結果；要取消也可以直接把狀態改成「已取消」。
- **備份還原**：打開雲端硬碟備份資料夾裡的試算表，把需要的工作表內容複製回來即可；備份檔沒有程式，不會自己發推播。
- **行業清單**：試算表「行業」欄的下拉選單是建議值，會員自己輸入其他文字也可以。
- **電話顯示同意**：會員在 App 同意後，「會員」工作表「同意顯示電話」欄會填入時間；撤回會清空。幹部看活動報名名單時仍看得到報名者電話（那是報名時留給主辦單位的，與通訊錄無關）。
- **修改同意條文**：在 `liff/js/app.js` 最上方的 `PHONE_TERMS`，一項一行；改完把 `PHONE_TERMS_VERSION` 也改掉，提醒自己這是新版本。

## 安全性設計

- 前端送來的身分一律不採信：每次請求都用 LINE ID Token 向 LINE 驗證，取得 userId 後才查名冊決定權限。
- 會員通訊錄不會回傳 LINE userId；未授權的動作在後端就擋掉，不只是前端隱藏按鈕。
- 綁定比對失敗 5 次會鎖 1 小時，避免有人猜手機號碼冒用。
- 同一位會員只能綁一個 LINE 帳號，換綁要管理員解除。
- 使用者輸入寫進試算表前會處理 `= + - @` 開頭的內容，避免試算表公式注入。
- 幹部不能建立比自己等級高的內容，也不能修改等級比自己高的會員。
- 限制：Apps Script 讀不到 HTTP 標頭，無法驗證 Webhook 簽章，所以 Webhook 只做「回覆」，不改任何資料。

## 疑難排解

| 狀況 | 處理 |
|---|---|
| 開啟顯示「後端尚未設定」 | 執行「檢查設定」補齊金鑰（金鑰立即生效，不用重新部署） |
| 只有自己打得開，其他會員打不開 | LINE Login channel 還是 Developing，改成 Published |
| 在 LINE 裡打開出現黃色「示範模式」 | `config.js` 的 LIFF_ID 或 API_URL 沒填，或手機還在用舊檔（GitHub Pages 約 10 分鐘更新） |
| 綁定一直找不到 | 確認名冊的姓名與手機和輸入完全相同（空白、+886 會自動處理） |
| 推播失敗「Authentication failed」 | Channel access token 錯誤或已重發，重新設定 |
| 推播成功但有人沒收到 | 對方沒加官方帳號好友或已封鎖；App 首頁會提示未加好友的人 |
| 推播找不到人 | LINE Login 與 Messaging API channel 不在同一個 Provider |
| 改了程式沒生效 | 沒有部署「新版本」 |
| 想先給理監事看畫面 | `config.js` 設 `DEMO: true` 上傳，或直接開 `index.html` |
| 報到 QR code 顯示不出來 | 網站上少了 `js/qrcode.js`，重新上傳 `js` 資料夾 |
| 掃 QR 顯示「報到碼不正確」 | 幹部換過報到碼，請重新掃新的 QR |
| iPhone 按「加入行事曆」沒反應 | 改用「Google 日曆」選項，或請對方自行在行事曆輸入；.ics 在部分手機瀏覽器會被當成下載檔 |
| 出席統計數字不對 | 只算「類別」表勾了「計入例會出席」的類別、且「報名」工作表「出席」欄有時間的列；請假列不算 |
| 升級後會員專區打不開，顯示需要授權 | 新程式加了雲端硬碟權限：回到試算表執行任一個選單功能並按「允許」，再部署一次新版本 |
| 「年度交接」「調查」顯示找不到工作表 | 還沒執行「1. 初始化／修復工作表」 |
| 預約的通知沒送出 | 「檢查設定」看排程是否有 processScheduledPushes；「排程推播」工作表的「結果」欄會寫失敗原因（例如額度不足） |
| 自動備份失敗 | 「檢查設定」會顯示原因；多半是沒授權雲端硬碟，執行一次「立即備份試算表」並按允許 |
| 新增的類別沒出現在試算表下拉選單 | 選單「更新類別下拉選單」（App 裡會立即出現，不用等） |
| 畫面上方出現「系統已更新，請重新整理」 | 按「重新整理」即可；是網站檔案更新了、手機還在用舊檔 |
| 按了「重新整理」還是一直出現「系統已更新」 | 手機暫存的舊檔還沒過期（多半是 `index.html` 比 `js` 先上傳），最慢 10 分鐘會自己好；可以先按「稍後」。也確認網站上的 `js/app.js` 已經是新版 |
| 管理員看到「後端還是舊版本」 | Apps Script 貼上新程式後沒有「部署新版本」 |
| 例會報到時有人看到「目前使用的人比較多」 | 系統已自動重試 3 次仍忙碌，請他等幾秒再按一次；人多時可以分批掃 |
| 試算表改了，App 沒更新 | 等幾秒再按右上角重新整理；仍沒有，執行「1. 初始化／修復工作表」把修改觸發器裝回來 |
| 角色改了，圖文選單沒換 | 對方下次打開會員專區才會換；要立刻換就按「重新套用圖文選單」 |
| 建立圖文選單說「讀不到圖片」 | 網站上沒有 `img/richmenu/` 資料夾，或網址輸入錯（要填 `index.html` 所在的資料夾） |
| iPhone 按「訂閱行事曆」沒反應 | 用「複製訂閱網址」，到「設定 → 行事曆 → 帳號 → 加入帳號 → 其他 → 加入已訂閱的行事曆」貼上 |
| Google 日曆在手機加不進去 | Google 日曆只能用電腦網頁版用網址加入；加入後手機會自動同步 |
| 會費管理顯示「金額未定」 | 「會費標準」工作表的金額沒填 |
| 「連線狀況」顯示「直接連 Apps Script」 | `config.js` 的 `API_URL` 還是 Apps Script 網址，改成 Worker 網址並上傳 |
| 「連線狀況」顯示「加速層連不上，已改走 Apps Script」 | 到 Cloudflare 看 Worker 是否被停用或超過免費額度；試算表「檢查設定」也會顯示加速層狀態 |
| 設定加速層時顯示「D1 尚未綁定」 | Worker 的 Settings → Bindings 加上 D1，Variable name 一定要是 `DB` |
| 設定加速層時顯示「作廢通知失敗」 | Worker 的 `EDGE_SECRET` 和試算表填的不一樣（注意前後空白） |
| 秘書處改了試算表，會員要等幾分鐘才看到 | 「檢查設定」看加速層是否正常；作廢通知靠「試算表有修改就通知 App」的觸發器，重新執行「1. 初始化／修復工作表」會裝回來。最慢 10 分鐘暫存自己過期 |
